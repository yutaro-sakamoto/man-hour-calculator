# 次に持っていくものを書くとき

`dev-skills/` は**このリポジトリの設定ではない**。次のプロジェクトへ symlink
して使う置き場で、[docs/JOURNAL.md](../../docs/JOURNAL.md) の段 4 の行き先。
[AGENTS.md](../../AGENTS.md)「学んだことを持ち越す」も読むこと。

## 固有の名前を持ち込まない

`mhc-core` も `工数見積もり` も書かない。差し替える箇所は `<<< >>>` で囲む。

**シェルスクリプトだけは `@@NAME@@`。** `<<<` は bash の here-string なので、
`<<<FOO>>>` と書くとファイルが構文エラーになる (実際に踏んだ)。

## `name` はディレクトリ名と揃える

Claude Code は frontmatter の `name` で呼ぶ。ずれると**呼べないまま何も
起きない**。`./scripts/check-sync.sh` が見ているので、直したら回す。

`description` は**「いつ呼ぶか」**を書く。ここが呼び出しの判断に使われるので、
「何が書いてあるか」だけでは呼ばれない。日本語の語と、探しやすい英語の語を
両方入れる。

## 1 回しか踏んでいないものを移さない

段 4 に上げるのは「**別のプロジェクトでも出た**」もの。1 回のものを全部移すと
読めない長さになり、自分も読まなくなる。1 回のものは日誌に置いたままにする。

## 雛形は動かしてから置く

`assets/` に置くものは、そのままでは動かない箇所があるのはよいが、
**構文として壊れていてはいけない**。置く前に確かめる。

```sh
bash -n dev-skills/*/assets/*.sh
python3 -c "import yaml,glob;[yaml.safe_load(open(f)) for f in glob.glob('dev-skills/*/assets/*.yml')]"
```

## 日誌の書き方

`昇格:` の**最初の語**が段 (`未` / `rules` / `機械` / `skill` / `一過性`)。
後ろに置き場所を括弧で足してよい。綴りを間違えると静かに数から漏れるので、
`check-sync.sh` が値を見ている。

項目 1 件につき `昇格:` の行は必ず 1 本。数が合わないと検査が落ちる。
