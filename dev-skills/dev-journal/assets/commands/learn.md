このセッションで得た知見を `docs/JOURNAL.md` に書き残す。

$ARGUMENTS が空なら、**このセッションを振り返って**書く対象を自分で選ぶ。
$ARGUMENTS があれば、それについて書く。

```sh
./scripts/journal.sh new "<一行の要約>"
```

雛形が追記されるので、中身を埋める。

## 書くもの

- **読み違い** — 成功と失敗を取り違えた、出力を絞りすぎた、直したつもりだった
- **環境の地雷** — 道具の版、プラットフォーム差、0 始まりの添字
- **設計の判断と理由** — なぜその形にしたか。とくに「やらないと決めたこと」
- **検査をすり抜けた穴** — どの対象をモデル化していなかったか

## 書かないもの

- ふつうのバグ。**回帰テストを添えれば、テストが記録になる**
- 調べれば分かること
- **推測。** 実際に起きたことだけ書く

## 書いたあと

`昇格:` を決める。既定は `未`。ただし、その場で上げられるなら上げる。

- `grep` で破りを見つけられる → `scripts/check-sync.sh` に検査を足して `機械`
- テストで固定できる → テストを書いて `機械`
- 書き方の約束にすぎない → `AGENTS.md` か `.claude/rules/` に足して `rules`
- 上げる価値が無い → `一過性`。**判断したことを残す**

**段 3 (機械) に上げられないか、まず考えること。** 段 1 と 2 は候補を貯める
場所でしかない。

最後に `./scripts/journal.sh open` を回して、溜まっているものを 1 行で報告する。
