# 開発日誌

踏んだ穴・読み違い・設計の判断を追記していく。新しいものが上。
雛形は `./scripts/journal.sh new "<要約>"`、Claude Code なら `/learn`。

**書くだけでは効かない。昇格させる。** `昇格:` は次の 5 つのどれか。

| 値 | 意味 |
|---|---|
| `未` | まだ何にもしていない。応答の終わりにフックが数えている |
| `rules` | [AGENTS.md](../AGENTS.md) か `.claude/rules/` に書いた |
| `機械` | テスト / lint / `scripts/check-sync.sh` にした。**ここまで来て初めて守られる** |
| `skill` | [dev-skills/](../dev-skills/) に移した |
| `一過性` | 上げる価値が無いと判断した。判断したことを残す |

段は**最初の語**。後ろに「どこに置いたか」を括弧で足してよい
(`昇格: 機械 (scripts/check-sync.sh)`)。

ふつうのバグは書かない。**直す前の実装では落ちる回帰テストを添えれば、
テストのほうが記録になる。**

迷ったら「この決めごとを破ったコードは `grep` で見つかるか」を考える。
見つかるなら `scripts/check-sync.sh` に足して `機械` にする。

## 2026-09-25 — 入口を make にそろえたら、文書のコマンドが 2 つ動いていなかった

- 分類: 検証 / 読み違い
- 症状: README の `cargo test golden store_formats` は `cargo test` が名前の絞り込みを
  1 つしか取らないので、そもそもエラーで止まる。`cargo test --release fuzz` は
  名前に fuzz を含むテストしか拾わず、ABI (`fuzz_abi.rs`) と WASM の入口の
  ファジングを深く回していなかった。どちらも書いた本人が試していなかった
- 原因: 文書に生のコマンドを並べると、書いた時点で試さない限り誰も確かめない。
  Makefile を書く途中でも、行末の `##` の前の空白が変数の値に入り、
  `MHC_FUZZ_ITERS="20000   "` が Rust で数として読めず既定の回数に戻っていた
- 手当て: 入口を `make` に集め (`make help`)、文書は `make …` を名指しする。
  `check-sync.sh` が、文書の `make …` が Makefile にあること、呼べる
  ターゲットに説明があることを見る。変数は使う側で `$(strip …)` を通す
- 昇格: 機械 (`scripts/check-sync.sh` と `Makefile`)

## 2026-09-24 — 認証より先に本文を読んでいた (axum の抽出の順番)

- 分類: 設計 / 検証
- 症状: トークン無しの `POST /v1/users` が 401 ではなく 422 (本文の形の誤り) を返した。
  全ルートを認証無しで叩く検査を足して初めて見えた
- 原因: axum はハンドラの引数 (`Json<…>`) を**ハンドラより先に**組み立てる。
  認証はハンドラの中なので、誰の本文でも上限まで読み、形を検めていた
- 手当て: `/v1/` の前に認証だけの層を置く。本文の上限も正しい呼び出しの最大に
  合わせた (既定の 2 MiB では、上限いっぱいの添付がサーバでだけ落ちていた)
- 昇格: rules (`.claude/rules/security.md`)

## 2026-09-24 — `-----` で始まるパターンを grep に渡すと、黙って 0 件になる

- 分類: 検証
- 症状: 秘密鍵を探す検査が、わざと置いた鍵を見つけなかった
- 原因: パターンが `-----BEGIN` で始まり、grep が**引数**と読んだ。エラーにならず

## 2026-09-24 — ファジングは「歯があるか」を測ってから入れる

- 分類: 検証 / 設計
- 症状: 状態つきのファジングを入れた直後、番人を外しても**緑のまま**だった。
  モンキーテストは半分近くの手が「覆われていて押せない」で時間切れ、
  わざと `innerHTML` にした版を 4 本中 1 本しか捕まえなかった
- 原因: 空の状態から等確率で操作を撃つと、6 割が「見つかりません」で終わり、

  窓が開いていたら中だけを触る。**番人を 1 つずつ外して落ちることを測り**、
  届かない性質 (XSS) は筋書きのある検査 (`xss.spec.js`) に分けた。
  測ったら、入れたその日に 4 件見つかった (入れ物の所有者・非オブジェクトの
  JSON で panic・並びの崩れたファイル・innerHTML の残り)
- 昇格: 機械 (`service/fuzz.rs` / `fuzz_abi.rs` / `fuzz.test.ts` / `monkey.spec.js`)

## 2026-09-23 — 複雑度に上限を置き、カバレッジを C0 と C1 の両方で見るようにした

- 分類: 検証 / 設計
- 症状: カバレッジは Rust が行だけ。`if` の片側しか通っていなくても 100% に
  見える。関数の込み入り具合には何の歯止めも無かった
- 原因: 行網羅は stable で測れるが、Rust の分岐網羅は nightly の不安定機能で、
  後回しになっていた
- 手当て: `scripts/coverage.sh` に Rust の C0/C1 の基準を置き、分岐網羅には
  **版を固定した** nightly を使う (数え方が nightly のあいだに動くと、触っていない
  のに CI が赤くなるため)。複雑度は Rust = clippy の認知的複雑度、TS = ESLint の
  循環的複雑度で、上限は入れたときの最大値 (16 / 25)。道具を増やさずに測れる
  ものを選んだので物差しが揃っていない。README の表と設定のずれは
  `check-sync.sh` が見る。`.claude/settings.json` には新しい 2 本の許可を足した
  (毎回聞かれると回さなくなるため)
- 昇格: 機械 (`clippy.toml` / `web/eslint.config.js` / `scripts/coverage.sh` / `scripts/check-sync.sh`)
